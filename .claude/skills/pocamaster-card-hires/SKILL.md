# pocamaster：実物の写真でカードの画質を上げる

本人は日本語で、はじめてアプリを作っている人。説明は短く、丁寧な言い方（〜しました）で。進め方の細かい記録は docs/00_進捗メモ.md（最初に「次のセッションへの引き継ぎ」を読む。16〜20 回目は 85.〜95.）。

## 全体の流れ（1 回＝1 つの <回>。例 20261114）

1. どこを探すか決める → 2. Chrome で候補を集める（保存はしない）→ 3. 件数の表を見せて本人の了承をとる → 4. 保存 →
5. 照らし合わせ（裏で）→ 6. Claude が見比べ・透かし・端を確かめる → 7. 差し替え・ZIP・一覧・メモ・コミット →
8. 押して確かめるページと ZIP を本人に送る → 9. 本人「やりました」→ 合っていない組を戻す

長い作業なので、最初にチェックリストを出し、終わったものから消す（本人の決まり）。長い道具を動かしている間は、何をしているかを一言伝える。

## 1. どこを探すか

- 粗い・ぼかし・画像なしの数は `python tools/crop/review_todo.py`（約 2 分。最後の行に数が出る）。
- 「コレクション × 入手元」ごとの粗い枚数は、全部入りの ZIP の画像の高さ（300px 未満）を数える（manifest.json の collection・source ごと）。多い入手元から探す。
- 探し方は 3 段階。上から順に当たりが多く、だんだん減る（20 回目で 1 回 80 枚ほどまで減った）：
  1. コレクション名（＋お店の名前）で検索の 1 ページ目
  2. 同じ検索の 2〜5 ページ目（4 ページ目からは同じ出品が多い）
  3. 入手元・特典の名前で検索（「IVE パパジョンズ トレカ」「IVE withmuu ラキドロ」「IVE ELEVEN 特典 トレカ」など）
- 入れないと決めたもの（探さない）：in CINEMA の台湾版、SWIA TAIPEI 特典（前の画像がぼかしで、同じカードか決めきれない。本人が合っていないとした）。

## 2. 探し方（Claude in Chrome）

- メルカリ：`https://jp.mercari.com/search?keyword=IVE%20<言葉>%20トレカ`。続きのページは `&page_token=v1%3A1`（2 ページ目）・`v1%3A2`（3 ページ目）…を付ける。
- 結果のページは読み込みが遅い。すぐ数えると 50 件ほどしか取れない → 出品が出るのを待ち、上から下へ 2 回スクロールしながら `a[href*="/item/"]` の「出品番号・題名」を集める（1 ページ約 120 件）。集めた分は localStorage にためる（ページを移っても残る）。
- browser_batch は 1 回に 3〜4 ページまで（多いと時間切れになる。時間切れでも裏で進んでいることがあるので、ためた件数を確かめてから続ける）。
- 題名で絞る（コレクション名か、IVE・メンバー名を含むものだけ）。JavaScript の返り値は約 1,000 文字で切れるので、番号の一覧は `document.body` を `<pre>` に置き換えて get_page_text で読む。読んだ一覧は Write ツールでファイルにする（長い一覧を bash の heredoc に入れると壊れる）。
- お店の名前は日本語の呼び方でも探す（ミューコリ＝Music Korea、メイクスター＝Makestar、サウェ＝Soundwave、ケタポ＝Ktown4U、ソニミュ、スタシ など）。
- **カード 1 枚の出品**がいちばん良い（高さ 600〜1,000px）。6 枚コンプは 1 枚 400px ほど。20 枚以上のまとめ売りは小さいので当たらない。
- X：`https://x.com/search?q=<韓国語の語句>&f=media`。元の大きさは `pbs.twimg.com/media/<id>?format=jpg&name=orig`。告知画像はぼかし入り・重なりが多い。
- 見るだけ。ログイン・購入・いいね・コメントはしない。使い終わったタブは閉じる。

集めた番号は「組の名前 番号 番号 …」を 1 行ずつのファイルにして：

```
python tools/crop/hires_batch.py filter <回> <集めた番号.txt>   # 保存済みを外して review/hires/<回>a_候補.txt を作り、組ごとの件数を出す
```

## 3. 保存の了承（毎回必ず）

保存（ダウンロード）は、そのたびに本人の了承が要る（了承は一覧ごと。前の了承を次の一覧に広げない）。組ごとの件数の表・保存元（static.mercdn.net）・保存先・おおよその大きさ（1 件 約 0.12MB）・かかる時間を見せて聞く。候補は進捗メモに書いてコミットしておく（「保存は本人の了承待ち」）。

## 4〜5. 保存と照らし合わせ

`tools/crop/review/hires/<回>_組.json` に「組の名前 → コレクション名」を書く（「A||B」で複数のコレクションをまとめて照らし合わせられる。どのアルバムか分からない検索に使う。コレクションが多いほど遅い）。`"_見出し": {フォルダ名: 日本語の見出し}` を入れると、確かめるページの見出しになる。

```
python tools/crop/hires_batch.py download <回>   # 了承のあとだけ。新しい資料 <回>/<組>/ に保存（110 件を超える組は _A・_B に分ける）。画像は Git に入れない
python tools/crop/hires_batch.py find <回>       # 裏で（run_in_background）。10 本ずつ並べて動く。1,000 件で約 1 時間
```

名前は <回>a・<回>b…（フォルダの名前の順）。job は名前の順に読まれ、同じ枠ならあとの画像が勝つ。

## 6. 見比べ・透かし・端（Claude）

```
python tools/crop/mercari_hires.py sheet <名前>   # 候補（0.68 以上・1.15 倍以上、枠ごとに 1 つ）の新旧の並び → メルカリ見比べ/_作業/<名前>_候補N.jpg
```

候補の画像を読み、新旧が**同じ写真**かを 1 組ずつ決める。顔でメンバーを決めない（同じ写真かどうかだけ）。結果を `review/hires/<名前>.json` の `"ok": [番号…]`、理由を `"note"` に書く。外すもの：

- ちがうカード、写真の一部だけ（袋・机が大きく写る）、前の画像がぼかしで決めきれないもの
- カードの上に出品者の文字・シール・バーコード・「@ID」・匿名配送の札・サインがかかるもの
- 丸・六角などカードの形がちがうもの、ポラ（POLA）で枠の形がちがうもの
- 前の画像にだけお店の印（K-MONSTAR など）があるもの（印のあるなしで別の枠のことがある）
- レンチキュラー（パパジョンズ 6.0 など。角度で絵が変わるので、本人が合っていないとした）
- 自信のない組は入れてよいが、`"flag": [番号…]` に入れる（ページで印が付き、本人に特に見てもらえる）

```
python tools/crop/mercari_hires.py big <名前>   # OK のものを高さ 520px で並べる → _作業/<名前>_大きくN.jpg
```

大きい画像を全部読む。メルカリの写真には、カード全体に**出品者の薄い透かし**（「メルカリ」「@…」のくり返し）や小さな文字が入っていることがあり、小さい画像では見えない。あれば ok から外す。強い光の反射・ホロの虹も外す。端に背景・となりのカード・スリーブが残っていたら `"trim": {"番号": [左, 上, 右, 下]}`（割合、0.02〜0.06）で内側に寄せ、もう一度 big で確かめる。

## 7. 差し替え・ZIP・メモ

```
python tools/crop/hires_batch.py dedupe <回>    # 同じ枠が 2 つの名前にあるとき、前の名前から外す（ページの組と ZIP の枚数を合わせる）
python tools/crop/hires_batch.py apply <回>
python tools/crop/merge.py && python tools/crop/make_diff.py    # merge のあとは必ず make_diff（版の番号を書くのは make_diff だけ）
python tools/crop/review_todo.py                                # 粗いカードの数（前 → 後）
python tools/crop/hires_batch.py split <差分ZIP>                # 28MB を超えたら 1of2・2of2 に分ける（スマホに送れるのは 30MB まで）
```

- ZIP の枚数がページの組より少ないときは、新しい画像が前の画像と同じ大きさで差し替わらなかった組（そのまま報告に書く）。
- 進捗メモ：「状態」の行（全部入りの番号・iPhone に入れる ZIP の並び）と、新しい番号の項目（何をした・件数・外した理由・ページの URL）を書く。道具・設定・job・メモをコミット。**push は本人が「push して」と言ったときだけ。**

## 8. 本人に送る（押して確かめるページ）

```
python tools/crop/hires_batch.py page <回> <出力フォルダ> <見出し>    # 例：… page 20261114 <scratchpad>/site20 20回目
```

- 出力フォルダの `mikurabe_<回>.html` を Artifact で公開する（root＝出力フォルダ、files＝files.json の一覧、capabilities `{"db": {}}`）。画像が 255 枚を超えるときは、2 回目の公開で残りの files を足す。
- 左＝新しい写真、右＝前の画像。本人が 1 組ずつ「合っている／合っていない」を押す（本人が選んだやり方。JPEG を送るより見やすい）。
- 差分 ZIP は SendUserFile（display: attach）で送る。取り込む順（No.xx のあと）を書く。場所を書くだけにしない。
- 報告は短く：差し替えた枚数、粗いカードの数（前 → 後）、組ごとの表、外した理由、特に見てほしい組、ZIP、次の候補、コミットしたこと（push はしていない）。

## 9.「やりました」のあと

ArtifactData でページの db の `checks` を `v == "ng"` で読む（0 件のときは、ほかの組が ok で入っているかも確かめる＝押していないのと区別する）。

```
python tools/crop/hires_batch.py ng <回> a-03 e-01 …    # ok から外して apply まで行う
python tools/crop/merge.py && python tools/crop/make_diff.py
```

前の画像に戻す小さな差分 ZIP（No.xx）ができるので送る。進捗メモに「本人の確認」を書いてコミット。合っていないが 0 なら、メモだけ書く。

## 画像のルール（本人の決まり）

- カードの上に人の ID・透かしがある画像は使わない。お店の印（SuperStar STORE の斜めの文字、K·MONSTAR のロゴ、中国のお店の名前など、カードやスリーブに印刷されたもの）は使ってよい。
- 明るさは上げない（白っぽくなる）。彩度は上げてよいが、今の流れでは補正しない。
- 今の画像より 1.15 倍以上大きいときだけ差し替える。
- ウエハースの「SAMPLE」入りの画像は、文字のない実物の写真に差し替えてよい。
