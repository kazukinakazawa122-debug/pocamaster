# 03. データ設計（pocamaster）

- 作成日：2026-09-27
- 版：v0.1（たたき台）

---

## 1. 全体像
アプリに保存するデータは、次の 6 種類の「表」に分けて持つ。

```
メンバー（6 人）
   │
   │ 1 人のメンバーは、たくさんのカードを持つ
   ▼
コレクション ──(1 つのコレクションに、たくさんのカード)──▶ カード ──▶ 画像（あれば）
                                                         │
                                                         └──▶ 状態の変更履歴

獲得した実績（第 2 段階）
```

保存先は iPhone の中のブラウザ用データベース（IndexedDB）。サーバーには送らない。

---

## 2. 各データの項目

### 2.1 メンバー（members）
最初から 6 人分を用意しておく。基本的に編集しない。

| 項目 | 意味 | 例 |
|---|---|---|
| id | 識別番号 | `wonyoung` |
| name | 表示名 | ウォニョン |
| order | 並び順 | 4 |
| color | メンバーカラー | ピンク |

| 並び順 | メンバー | 色 |
|---|---|---|
| 1 | ユジン | 青 |
| 2 | ガウル | オレンジ |
| 3 | レイ | 黄 |
| 4 | ウォニョン | ピンク |
| 5 | リズ | 緑 |
| 6 | イソ | 赤 |

（具体的な色コードは 04_画面設計 で決める）

### 2.2 コレクション（collections）
| 項目 | 意味 | 例 |
|---|---|---|
| id | 識別番号 | `kr-mini-1-ive-ive` |
| name | 名前 | I've IVE |
| type | 種別 | アルバム（韓国盤） |
| releaseDate | 発売日・開催日 | 2023-04-10 |
| coverImageId | カバー画像（本人が登録する。なければ仮カバーを表示） | なし |
| createdAt | 登録した日時 | 2026-09-27 21:00 |

**種別（type）の選択肢**
`アルバム（韓国盤）` / `アルバム（日本盤）` / `シーズングリーティング` / `ファンミ・ファンコン` / `ライブ・ツアー` / `ポップアップ` / `その他`

### 2.3 カード（cards）
| 項目 | 意味 | 例 |
|---|---|---|
| id | 識別番号 | 自動で付ける |
| collectionId | どのコレクションか | `kr-mini-1-ive-ive` |
| memberIds | 写っているメンバー（1 人以上） | `[wonyoung]`、ユニットなら `[yujin, wonyoung]` |
| source | 入手元 | Soundwave 特典 |
| version | バージョン（空欄可） | ver.2 |
| imageId | 登録した画像（なければ空） | なし → 仮カード表示 |
| status | 状態 | `未所持` / `所持中` |
| statusChangedAt | 状態を最後に変えた日時 | 2026-09-27 21:05 |
| order | コレクション内の並び順 | 12 |

- 新しく作ったカードの状態は `未所持`
- 仮カードの表示は「コレクション名＋メンバー名＋入手元＋バージョン」
- ユニットカード・グループカード：1 枚のカードに複数のメンバーを登録する
  - 仮カードのメンバー名は「ユジン・ウォニョン」のように並べる。6 人全員なら「全員」と表示
  - メンバー別タブでは、そのメンバーが写っているカードをすべて表示する

### 2.4 画像（images）
画像はサイズが大きいため、カードとは別に保存する（一覧の表示を軽くするため）。

| 項目 | 意味 |
|---|---|
| id | 識別番号 |
| full | 拡大表示用の画像（長い辺 1200px ほどに縮めて保存） |
| thumb | 一覧用の小さい画像（長い辺 400px ほど） |

- 登録するとき、自動で縮めて保存する（iPhone の容量を使いすぎないため）

### 2.5 状態の変更履歴（statusHistory）
第 2 段階の「収集履歴・グラフ」（F-24）のためのデータ。
**グラフは第 2 段階だが、記録は第 1 段階から始める**（あとから作ると、それまでの履歴が残っていないため）。

| 項目 | 意味 | 例 |
|---|---|---|
| id | 識別番号 | 自動 |
| cardId | どのカードか | … |
| from | 変更前の状態 | 未所持 |
| to | 変更後の状態 | 所持中 |
| changedAt | 変えた日時 | 2026-09-27 21:05 |

### 2.6 獲得した実績（achievements）※第 2 段階
| 項目 | 意味 | 例 |
|---|---|---|
| key | どの実績か | `first-complete` |
| unlockedAt | 獲得した日時 | 2026-10-01 |

実績の種類（名前、条件、アイコン）はアプリ側で決めておき、ここには「いつ獲得したか」だけを保存する。

## 3. コンプリート率の計算
`所持中` のカードだけを数える。

| 種類 | 計算式 |
|---|---|
| コレクション別 | そのコレクションの `所持中` 数 ÷ そのコレクションのカード数 |
| コレクション内のメンバー別 | そのメンバーの `所持中` 数 ÷ そのメンバーのカード数（そのコレクション内） |
| 全体 | 全コレクションの `所持中` 数 ÷ 全カード数 |
| 全体のメンバー別 | 全コレクションでのそのメンバーの `所持中` 数 ÷ そのメンバーの全カード数 |

- メンバー別の計算では、**そのメンバーが写っているカード**（ソロとユニット・グループの両方）を数える
  - 例：ユジンとウォニョンのユニットカード 1 枚は、ユジンの進捗にもウォニョンの進捗にも 1 枚として入る
  - コレクション別と全体の計算では、ユニットカードも 1 枚として数える（重ねて数えない）
  - そのため、メンバー別のカード数を足しても、コレクションのカード数とは一致しない
- カードが 0 枚のコレクションは「—」と表示し、率の計算からは除く
- 100% になったら「コンプリート」とする

## 4. 初期データ
- Claude が調べて作った下書きを、本人が確認してから取り込む
- 形式：表計算ソフトで確認しやすい **CSV**（コレクション用とカード用の 2 ファイル）
- アプリはこの CSV を取り込み用の形式に変換して読み込む
- 追加で取り込むときは、すでにあるカードの状態を上書きしない

**カード CSV のイメージ**
| collection | member | source | version |
|---|---|---|---|
| I've IVE | ウォニョン | 本体封入 | A ver. |
| I've IVE | ウォニョン | Soundwave 特典 | ver.1 |
| I've IVE | ウォニョン | Soundwave 特典 | ver.2 |
| I've IVE | ユジン/ウォニョン | ○○ 特典 | ユニット |

- ユニットカードは、メンバー名を `/` で区切って書く

## 5. バックアップ
- 書き出し：すべてのデータ（画像も含む）を **1 つのファイル（.zip）** にまとめ、iPhone の「ファイル」アプリに保存する
- 読み込み：そのファイルを選ぶと、中身をまるごと戻す（今のデータは置き換わる。実行前に確認を出す）
- 最後にバックアップした日を記録し、**14 日**取っていなければホーム画面でお知らせする
